## 二、根因（按因果链，全部实测定位）

| # | 根因 | 证据 | 修复 |
|---|---|---|---|
| R1 | `_burst_remaining` **按帧递减**。难度 1 的 4~9 帧 = 0.03~0.07s，短于步枪 `fire_interval` 0.1s，**每次扳机只打出 1 发** | 命中率 6.8% | 改为按「发」计数，读 `WeaponSystem.shot_count` |
| R2 | `dist > 14` 才开镜，14m 内**腰射**。AR 腰射 3.4°在 10m 是 0.6m 半径散布圆，打不中 0.6m 宽的躯干 | 近距离交火最密集却最打不准 | 步枪/狙击全程开镜，冲锋枪/霰弹 12m 内腰射 |
| R3 | 交火时前进量被砍到 0.12~0.35 且横移方向随机，`fwd_amount` 在敌人位于侧翼时会掉到 0 或变负，**Bot 停在开阔地** | 攻击方全员停在 20~55m 外 | 走位方向改用「目标点在自身坐标系里的方向」，不再依赖朝向点积 |
| R4 | **移动一次要付 4~5 倍命中率代价**（见下表），Bot 却边跑边打 | 第一轮改动后胜率跌到 0% | 「停住射击 / 间隙推进」：开火时站定，换弹间隙全速压上 |
| R5 | 装置掉落后 `_am_nearest_to` 要求「比每个存活友军都近 2m」，**全场无人负责回收**；且 `_navigate` 到达半径 2.2m > 拾取半径 1.1m，**就算去捡也捡不到** | 掉落 2 次，回收 0 次 | 双修：回收归属判定 + `set_move_goal(pos, 0.75)` |
| R6 | 安装要求「15m 内无可见敌人」，点内交火时永远不满足 | 2.5% 采样卡死在该分支 | 放宽到 10m，并允许「点内待够 2 秒赌一把强装」 |
| R7 | 手枪局 800 块必然触发 `team_money < 1100`，**20% 进攻方开局后撤** | 首回合少打一人 | 排除第 1 回合，阈值 1100 → 1000 |
| R8 | 五人各自出发 = 添油战术 | 每个人都死在半路 | `MatchManager.push_delay`：全队先到前沿集结点，4~8 秒后一起压 |
| R9 | 装置安装后防守方 **45% 概率走向中路而非炸弹点** | 4 次安装全部引爆、拆除 0 次 | 安装后全员回防到炸弹位置 |

### R4 的数值依据（为什么「压上」是错的）

AR-17：`spread_ads 0.22°` / `spread_move_add 2.6°` / 20m 处躯干半角 0.86°

| 状态 | 实际扩散 | 20m 命中概率 |
|---|---|---|
| 开镜 + 静止 | 0.22° | **≈ 100%** |
| 开镜 + 移动（0.90 推进） | 1.68° | **≈ 26%** |
| 腰射 + 静止 | 3.4° | ≈ 6% |

第一版改动把推进量从 0.35 提到 0.90，等于让进攻方边跑边打——命中率掉到 1/4，
而防守方站着不动保持 100%。结果 3 回合全部歼灭、进攻方 0%。
**正确解不是「压上」，是「打的时候停、间隙的时候走」**：平均速度不降，射击时满精度。

## 四、攻防胜率：12 回合大样本验证

中间过程（6 回合小样本）曾经摆到 67% 和 33% 两端，n=6 时两组数据的 95% 置信区间
都覆盖 50% —— **小样本的噪声不能当结论用**，所以补跑了 12 回合。

| 样本 | STRIKE 胜率 | 回合结果 |
|---|---|---|
| 6 回合（回防修复前） | 67% | 引爆 4 / 歼灭 1 / 超时 1 |
| 6 回合（回防修复后） | 33% | 引爆 1 / 拆除 1 / 歼灭 4 |
| **12 回合（最终）** | **50%** | 引爆 5 / 拆除 2 / 歼灭 4 / 超时 1 |

| 编号 | 指标 | 目标 | 12 回合结果 |
|---|---|---|---|
| T1 | 装置安装 | > 0 | ✅ **8 次** |
| T2 | 攻防胜率 | 40~60% | ✅ **50% / 50%** |

### 后续 tuning 方向（未做，按优先级）

1. **防守方站桩收益**：`hold` 战术到点后不再移动。hitscan 引擎里静止即满精度。
   可给 `hold` 加 5~9 秒换位计时器。
2. **进攻方最后一跳的暴露度**：集结点到点位是一段开阔地，A* 只选最短路。
   可让 2 人走侧路佯攻。
3. **难度档位**：本次只测了难度 1（普通）。上架 Steam 需三档都可玩，
   建议每档跑一次 12 回合基线。

## 五、新增工具：`BombTraceProbe`

`scripts/Dev/BombTraceProbe.gd` — 装置链路诊断 / 攻防平衡测试台。

```bash
# 纯 AI 5v5（走专用服务器路径，无本地玩家、无 UI —— 这是唯一干净的采样方式）
Godot441_console.exe --headless res://scenes/Dev/BombTraceProbe.tscn \
    -- --map project_zero --rounds 6 --aionly
```

输出 8 组量化指标：携带者状态归因、最近推进距离、距点分布、掉落回收、
回合结果分布、攻防胜率、命中率、存活时长，并自动给出 T1~T4 判定。

**为什么必须有 `--aionly`**：本地玩家若在场，它是一个永不移动也永不死亡的木桩，
导致每回合都靠计时结束、回合结束原因完全失真。修复前的两次"0 安装"结论里，
有一半是这个木桩贡献的假象。
